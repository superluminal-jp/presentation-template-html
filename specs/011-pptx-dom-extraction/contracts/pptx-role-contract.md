# Contract: `data-pptx` 役割属性(HTML 作者向け)

**Feature**: 011-pptx-dom-extraction | **Data model**: [../data-model.md](../data-model.md)

正本デックのコンポーネントが、編集可能な PowerPoint オブジェクトへ変換されるための契約。
変換器はこの語彙**だけ**を知る。コンポーネント名やクラス名は一切参照しない。

## 既定は「本文は自動で出る」

**本文テキストは、マークしなくても PPTX に出る。** 具体的には
「**直接の子テキストノードに非空白を持つ要素**」が 1 つのテキストボックスになる
(入れ子のインライン要素は同じボックス内の *run* になる)。

`data-pptx` は、この既定を**上書きしたいときだけ**付ける:

- 出したくない → `ignore`
- 面(塗り・境界)も出したい → `shape` / `group`
- 束ね方を変えたい → `text`(部分木を 1 ボックスに)
- 別種のオブジェクトにしたい → `table` / `chart` / `line` / `image`

### なぜこの向きか(設計判断)

当初の計画は逆(既定は出力せず、出したい要素をすべて明示マーク)だった。実装時に
既存 28 スライドへ適用したところ、**約 250 個**のマークが必要になり、かつ
**新しい本文を書いてマークを忘れると PPTX から黙って消える**という故障モードを
持ち込むことが分かった。これは本機能が解消しようとしている「8 枚の未変換」と
同じ「静かな欠落」である。

向きを反転させると、必要なマークは **113 個**まで減り、故障モードが
「余計なものが出る(目で見て分かる・直せる)」側に倒れる。新しいスライドや
コンポーネントを足したとき、**HTML 側も変換器側も無変更で PPTX に現れる**ため、
FR-009 の趣旨(正本に追随する)をより強く満たす。

## 原則

1. **本文は自動**。直接テキストを持つ要素がテキストボックスになる。
2. **役割属性は描画に影響しない**。CSS セレクタの対象にしてはならない。
3. **コンポーネントは語彙の合成で表現する**。語彙に写せない視覚表現(グラデーション、
   影、擬似要素による本文文字)を新規コンポーネントに持ち込まない。

## 語彙

| 値 | PPTX 上の対応物 | 付ける対象 | 走査の扱い |
|---|---|---|---|
| (なし) | 直接テキストがあればテキストボックス | 既定 | 子孫へ続行 |
| `text` | テキストボックス 1 個 | 部分木をまとめたいリスト等 | マーク済み子孫のみ拾う |
| `shape` | 矩形(角丸可) | 塗り・境界だけの面 | 子孫へ続行 |
| `line` | 直線 | 罫線、コネクタ | 停止 |
| `table` | ネイティブ表 | `<table>` | 停止 |
| `chart` | ネイティブグラフ | `data-chart` を持つ SVG | 停止 |
| `image` | 画像 | `<img>` | 停止 |
| `group` | グループ | 複合コンポーネントの根 | 子孫をグループへ |
| `ignore` | 出力しない | 装飾・注釈 | 部分木ごと停止 |

## 作成規則

### テキスト(既定)

- 本文は実 DOM のテキストノードであること。擬似要素で**本文**を描かない。
  - 唯一の例外は `li::before` の**リストマーカー**(`.checklist` の `✓` など)。
    これは本文ではなく箇条書き記号であり、抽出器が PPTX のネイティブ箇条書き文字
    (`buChar`)として持ち上げるため失われない。1 文字に限る。
- 要素内の部分着色(`<span class="u-accent">` 等)は混在ランとして保持されるため、
  着色のためにボックスを分割しない。
- ブロックレベルの子要素は自動的に別段落になる(`.callout` のタイトル行など)。
- 面(塗り・境界)を持つ要素は、テキストと面が**1 つのオブジェクト**になる
  (PowerPoint で最も編集しやすい形)。面を持たない要素は、実テキストの描画矩形に
  詰めて配置される(先行するインライン図形と重ならない)。

### `shape` / `group`

- **複数の別位置テキストを含む面**(`.tile` / `.step` / `.node` / `.quadrant` / `.col`)
  には `group` を付ける。面と各テキストが 1 グループになり、PowerPoint 上で
  一塊として移動できる。
- **面だけで文字を持たない要素**(`.progress` / `.legend__swatch` / `.divider`)には
  `shape` を付ける。
- 面を持たない複合(`.stat` / `.key` / `.legend__item`)も `group` でまとめられる。
- グラデーション・影は PPTX に対応物が無い。単色塗りと 1 本の境界で表現する。
  片側だけの境界(callout の左帯)は細い矩形として描かれる。

### `table`

- `<table>` / `<thead>` / `<tbody>` / `<th>` / `<td>` の意味的マークアップであること。
- ヘッダ行は `<th>` で表現する(ネイティブ表のヘッダ書式へ写される)。
- 表を `<div>` の格子で模さない。模した場合はネイティブ表にならない。

### `chart`

- `data-chart` に下記 JSON を持つこと。属性は**単引用符**で囲む(値に `"` を含むため)。

```json
{
  "type": "bar | line | bar100 | doughnut | scatter",
  "categories": ["Q1", "Q2", "Q3"],
  "series": [
    { "name": "企画", "values": [80, 100, 70] },
    { "name": "開発", "values": [120, 150, 180] }
  ]
}
```

- `scatter` のみ、各系列が `x`(横軸値の配列)を併せ持つ。
- **整合制約**(`check:pptx` と `tests/visual/chart-encoding.spec.mjs` が検証。違反はビルド失敗):
  - 円系以外: `series.length` == `data-series`、`series[].name` の集合 == `text.series-label` の文言の集合
  - 円系(`doughnut`): `categories.length` == `data-series`、`categories` の集合 == `series-label` の集合
    (円グラフでは直接ラベルが系列ではなくカテゴリを指すため)
  - `scatter` を除き `series[].values.length` == `categories.length`
- 系列色は `--cat-1..7` を系列順に自動割り当て。個別指定しない。

### `ignore`

- 子孫ごと出力対象から外れる。
- 対象: `.slide__annotation`(設計意図パネル)、`.slide__signpost`、`.scrim`、
  支援技術専用テキスト、装飾 SVG アイコン。

## 新規コンポーネントのチェックリスト

- [ ] 本文文字がすべて実 DOM のテキストノードである(擬似要素で描いていない。マーカーを除く)
- [ ] 面 + 複数テキストの複合なら、根に `data-pptx="group"` を付けた
- [ ] 文字を持たない面には `data-pptx="shape"` を付けた
- [ ] 面は単色塗り + 境界で表現している(グラデーション・影を使っていない)
- [ ] 表形式のデータは `<table>` で表現している(`<div>` の格子で模していない)
- [ ] グラフは `data-chart` payload を持ち、整合制約を満たす
- [ ] 装飾要素に `data-pptx="ignore"` を付けた
- [ ] 役割属性を CSS セレクタの対象にしていない
- [ ] `npm run test:visual` の差分が 0(役割属性の追加が描画を変えていない)
- [ ] `npm run build:pptx && npm run check:pptx` が緑
