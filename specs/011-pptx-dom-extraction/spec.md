# Feature Specification: 編集可能 PPTX への DOM 実測変換(正本一元化)

**Feature Branch**: `011-pptx-dom-extraction`

**Created**: 2026-09-15

**Status**: Draft

**Input**: User description: "デジタル庁デザインシステムに準拠したHTMLのテンプレートの改善を提案。編集可能なパワーポイントファイルに効果的に効率的に実践的に変換可能なコンポーネントで構成する"

## Overview

現行の PPTX 書き出し `scripts/pptx/build-pptx.mjs` は、正本デック `index.html` とは独立に
**文言と座標を手書きした第二の正本**として存在する。その結果、正本に追加されたスライドが
PPTX に届かず、文言も陳腐化している(下記「現状の計測値」)。

本機能は、この構造を**正本一元化**へ転換する。すなわち (1) HTML コンポーネントを
「PPTX ネイティブ・オブジェクトへ 1:1 で写せるプリミティブの合成」として再定義する抽出契約
(`data-pptx` 役割属性)を導入し、(2) 実レンダリングした DOM の**算出済み矩形と計算済みスタイル**を
読み取る汎用変換器で PPTX を生成し、(3) 乖離を検出する検証ゲートを `npm run verify` に組み込む。

変換器は「どのスライドがあるか」を知らない。知っているのは役割属性の語彙だけであり、
正本にスライドやコンポーネントが増えれば、変換器のコードを変更せずに出力へ追随する。

### 現状の計測値(2026-09-15 時点、本機能の出発点)

| 観点 | 計測値 |
|---|---|
| スライド枚数 | `index.html` 28 枚 / `build-pptx.mjs` のビルダー 20 個(**8 枚が未変換**) |
| 本文の重複 | `build-pptx.mjs` 内の日本語リテラル **214 個** |
| 内容の陳腐化 | 表紙メタが HTML「20コンポーネント」に対し PPTX「12コンポーネント」 |
| 座標 | `y: 2.15` 等の手指定(`scripts/pptx/README.md` に「位置は手指定」と明記) |
| ドリフト検知 | `build:pptx` は `verify` 対象外 — **乖離を止める仕組みが無い** |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 正本デック全枚数が自動で PPTX になる (Priority: P1)

テンプレート保守者が `index.html` にスライドを追加・修正したとき、変換器へ手を入れることなく
`npm run build:pptx` の出力へその変更が反映されることを期待する。文言はどこにも二重に存在しない。

**Why this priority**: 未変換 8 枚・リテラル 214 個という現行の欠損と重複の直接の解消であり、
以降のすべての価値(ネイティブ編集・検証ゲート)がこの一元化の上に乗る。これ単体で
「HTML を直せば PPTX が直る」という MVP が成立する。

**Independent Test**: `index.html` の任意のスライドの見出し文言を変更して `npm run build:pptx` を
実行し、変換器のソースを一切編集せずに出力 PPTX の当該スライドへ反映されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 正本デックが 28 枚ある状態, **When** `npm run build:pptx` を実行する, **Then** 出力 PPTX のスライド数がライブの `.slide` 数と一致する。
2. **Given** 変換器のソース, **When** 日本語のコピーを検索する, **Then** 本文コピーのリテラルが 0 件である(スライド固有の文言を持たない)。
3. **Given** `index.html` に新しいレイアウトのスライドを 1 枚追加した状態, **When** `npm run build:pptx` を実行する, **Then** 変換器のコード変更なしに当該スライドが出力へ現れる。
4. **Given** 出力 PPTX, **When** PowerPoint で本文テキストを選択する, **Then** ラスタ画像ではなく編集可能なテキストボックスとして選択・編集できる。

---

### User Story 2 - PowerPoint 上でそのまま編集できるネイティブ・オブジェクト (Priority: P2)

受け取った人が PowerPoint 上で、表のセルを書き換え、グラフの数値を差し替え、
コンポーネントを一塊で移動できることを期待する。

**Why this priority**: 「編集可能」の実質を決める。US1 の一元化が成立していれば、
役割属性を表・グラフ・グループへ広げることで段階的に価値を積める。

**Independent Test**: 出力 PPTX を PowerPoint で開き、`.data-table` 由来の表がセル単位で編集でき、
多系列グラフがグラフオブジェクトとしてデータ編集でき、`.callout` 等が 1 グループとして移動できることを確認できる。

**Acceptance Scenarios**:

1. **Given** `.data-table` を含むスライド, **When** 出力 PPTX の当該箇所を選択する, **Then** ネイティブ表オブジェクトであり、セルの追加・編集ができる。
2. **Given** 多系列グラフを含むスライド, **When** 出力 PPTX の当該箇所を選択する, **Then** ネイティブグラフオブジェクトであり、系列データを編集できる。
3. **Given** `.callout` 等の複合コンポーネント, **When** 出力 PPTX 上でその一部をクリックする, **Then** コンポーネント全体が 1 グループとして選択され、まとめて移動できる。
4. **Given** 出力 PPTX, **When** PowerPoint で新規に図形やグラフを挿入する, **Then** 既定色が DS のプライマリ青である(既存の `theme1.xml` 差し替えを維持)。

---

### User Story 3 - 乖離を止める検証ゲート (Priority: P3)

テンプレート保守者が、正本と PPTX の乖離を人手のレビューではなく自動検証で防げることを期待する。

**Why this priority**: 現行の乖離(8 枚欠損・文言陳腐化)は `build:pptx` が `verify` の外にあることが
構造的原因であり、これを閉じなければ US1/US2 の成果は再び腐る。US1/US2 の後に配線できる。

**Independent Test**: `index.html` にスライドを 1 枚追加して PPTX を再生成しないまま
`npm run verify` を実行すると、枚数不一致で失敗することを確認できる。

**Acceptance Scenarios**:

1. **Given** 正本にスライドを追加し PPTX を再生成していない状態, **When** `npm run verify` を実行する, **Then** 枚数不一致を理由に失敗する。
2. **Given** 正本と同期した PPTX, **When** `npm run verify` を実行する, **Then** 全工程が緑になる。
3. **Given** 正本の見出し文言を変更し PPTX を再生成していない状態, **When** `npm run verify` を実行する, **Then** テキスト不一致を理由に失敗する。

---

### Edge Cases

- 擬似要素で本文文字を描いている箇所(`.quote::before` の引用符)は DOM 抽出で消失する。装飾か本文かを判別する手段が要る。
- インライン SVG(11 箇所)のうち、グラフはネイティブグラフ化の対象、tree コネクタは線図形化の対象、その他装飾は対象外。この 3 分岐を判別する手段が要る。
- グラデーション・影(6 箇所)は PPTX に忠実な対応物が無い。
- JS で実行時に描画される要素(`js/tree-connectors.js` のコネクタ)は、抽出時点で描画が完了している必要がある。
- 濃色スライド(`--text-on-accent` 系)で、計算済みスタイルから前景色を取ると反転規則を自動的に拾えるか。
- 折り返されたテキストの矩形は、PPTX のフォント・行送りの差により同一幅で同一行数にならない可能性がある。
- `.u-accent` のような 1 テキストボックス内の部分着色(混在ラン)を保つ必要がある。

## Requirements *(mandatory)*

### Functional Requirements

#### 抽出契約(HTML 側)

- **FR-001**: システムは、PPTX ネイティブ・オブジェクトへの写像を宣言する**役割属性 `data-pptx`** の閉じた語彙を定義し、文書化しなければならない(MUST)。語彙は `text` / `shape` / `line` / `table` / `chart` / `image` / `group` / `ignore` とする。
- **FR-001a**(実装時に改訂): 本文テキストは役割属性を要さず、**直接の子テキストノードを持つ要素が自動的にテキストボックスになる**ものとする(MUST)。役割属性はこの既定を上書きする目的にのみ用いる。
  - **改訂理由**: 当初の「既定は出力しない(出す要素をすべて明示マーク)」では既存 28 スライドに約 250 個のマークが必要で、かつ**マークを忘れた本文が PPTX から黙って消える**故障モードを生む。これは本機能が解消しようとしている「8 枚の未変換」と同種の静かな欠落であり、目的に反する。反転後は必要なマークが 113 個に減り、故障モードが「余計に出る(可視・修正容易)」側に倒れ、新規スライドが HTML 側も変換器側も無変更で PPTX に現れる。詳細は contracts/pptx-role-contract.md。
- **FR-002**: 正本デックの各コンポーネントは、この語彙のプリミティブの合成として表現されなければならない(MUST)。語彙外の視覚表現に依存してはならない(MUST NOT)。
- **FR-003**: 本文として読まれる文字は、実 DOM のテキストノードでなければならない(MUST)。擬似要素(`::before`/`::after`)で本文文字を描いてはならない(MUST NOT)。純粋な装飾の擬似要素はこの限りではない。
  - **例外(実装時に確定)**: `li::before` の 1 文字リストマーカー(`.checklist` の `✓`)は本文ではなく箇条書き記号であり、抽出器が PPTX のネイティブ箇条書き文字(`buChar`)として持ち上げるため失われない。この例外は `tests/visual/convertibility.spec.mjs` が「li かつ 1 文字」に限定して許可し、それ以外の擬似要素本文は失敗させる。
- **FR-004**: 役割属性の付与は、HTML の描画結果を変えてはならない(MUST NOT)。既存の視覚回帰スナップショットは差分 0 でなければならない(MUST)。
- **FR-005**: ネイティブグラフ化の対象となる多系列グラフは、系列名・カテゴリ・数値からなる**データ payload** を DOM 上に保持しなければならない(MUST)。payload と既存の `data-series`(系列数)および `text.series-label`(直接ラベル)は整合していなければならない(MUST)。

#### 変換器(スクリプト側)

- **FR-006**: 変換器は、`index.html` を実レンダリングし、**算出済み矩形(`getBoundingClientRect`)と計算済みスタイル(`getComputedStyle`)**から PPTX を生成しなければならない(MUST)。スライド固有の座標をコード中にハードコードしてはならない(MUST NOT)。
- **FR-007**: 変換器は、スライド固有の本文コピーのリテラルを含んではならない(MUST NOT)。すべての文言は正本 DOM 由来でなければならない(MUST)。
- **FR-008**: 変換器は、正本に存在するすべての `.slide` を出力しなければならない(MUST)。出力スライド数はライブの `.slide` 数と一致しなければならない(MUST)。
- **FR-009**: 変換器は、対応するレイアウトの一覧を持ってはならない(MUST NOT)。正本に新しいレイアウトが追加されたとき、変換器のコード変更なしに出力へ追随しなければならない(MUST)。
- **FR-010**: 配色・フォント・寸法は計算済みスタイル由来でなければならない(MUST)。トークン解決値の手維持マップに依存してはならない(MUST NOT)。
- **FR-011**: `data-pptx="table"` はネイティブ表オブジェクトとして、`data-pptx="chart"` はデータを伴うネイティブグラフオブジェクトとして出力されなければならない(MUST)。ラスタ画像に落としてはならない(MUST NOT)。
- **FR-012**: `data-pptx="group"` を持つ要素は、その子孫を含む 1 つの PPTX グループとして出力されなければならない(MUST)。
  - **実装上の注記**: pptxgenjs 4.0.1 にグループ API は存在しない。emit 側は `objectName` にグループ印を付けるに留め、`scripts/pptx/group-xml.mjs` が生成後の `ppt/slides/slideN.xml` を走査して `<p:grpSp>` で包む。想定外の形(印が不連続・座標が読めない)なら包まずに平坦のまま残し、**常に開ける PPTX**であることを優先する。
- **FR-013**: 1 つのテキストボックス内の部分着色(`.u-accent` 等)は、混在ランとして保持されなければならない(MUST)。
- **FR-014**: 既存の共通チャーム(機密区分・著作権・ページ番号)および `theme1.xml` の DS 配色差し替えは維持されなければならない(MUST)。
- **FR-015**: 変換器は、実行時 JS による描画(tree コネクタ等)が完了した後の DOM を抽出しなければならない(MUST)。

#### 検証と文書

- **FR-016**: システムは、正本と出力 PPTX の乖離を検出する決定的なチェックを提供し、`npm run verify` に組み込まなければならない(MUST)。チェックは少なくとも (a) スライド数の一致、(b) 正本の見出しテキストが対応スライドに存在すること、を検証しなければならない(MUST)。
- **FR-017**: 既存の検証スイート(トークン Lint、相互参照、カバレッジ、スライド数、視覚回帰、アクセシビリティ、印刷、PDF 生成/ページ数)は全て緑を維持しなければならない(MUST)。
- **FR-018**: 新規のランタイム依存を追加してはならない(MUST NOT)。
- **FR-019**: 変更された公開契約(`npm run` スクリプト、`data-pptx` 語彙、PPTX 出力の構成)は、同一変更内で近接ドキュメント(`scripts/pptx/README.md`、`CLAUDE.md`、`docs/requirements.md` のフェーズ2 記述)へ反映されなければならない(MUST)。

### Key Entities

- **役割属性(Role attribute)**: `data-pptx` の値。DOM 要素と PPTX オブジェクト種の対応を宣言する。
- **スライド IR(Intermediate Representation)**: 抽出器が DOM から生成し、出力器が消費する中間表現。1 スライド = 図形・テキスト・表・グラフのフラットな並び + グループ階層。
- **抽出器(Extractor)**: 実レンダリングした DOM を走査し、役割属性と算出値からスライド IR を作る。
- **出力器(Emitter)**: スライド IR を PPTX オブジェクトへ書き出す。
- **チャートデータ payload**: 系列名・カテゴリ・数値。ネイティブグラフの編集可能性の源。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 出力 PPTX のスライド数がライブの `.slide` 数(現時点 28)と一致する。未変換スライド 0 枚(現状 8 枚)。
- **SC-002**: 変換器のソースにおけるスライド固有の日本語コピーのリテラルが 0 件(現状 214 件)。
- **SC-003**: `index.html` にスライドを 1 枚追加したとき、変換器のソース変更 0 行で出力へ反映される。
- **SC-004**: PowerPoint で開いたとき、本文がテキストボックス、`.data-table` がネイティブ表、多系列グラフがネイティブグラフとして編集できる(本文領域にラスタ画像 0 件)。
- **SC-005**: `npm run verify` が `check:pptx` を含めて全工程緑になる。
- **SC-006**: 役割属性の追加による HTML 視覚回帰スナップショットの差分が 0 件。
- **SC-007**: 正本と PPTX を意図的に乖離させた状態で `npm run verify` が失敗する(ゲートが機能することの反証テスト)。

## Assumptions

- 方式は利用者の選択により「B: DOM 実測抽出」とする。OOXML 直接生成・`.potx` テンプレート化は本機能の範囲外。
- 幾何の**ピクセル一致は非目標**。算出済み矩形に基づく近似であり、フォントメトリクスの差による折り返しの揺れは許容する(既存 README の方針を継承)。
- フォント埋め込みは pptxgenjs の制約により引き続き非対応。未導入端末では代替表示となる。
- 抽出には既存 devDependency の `@playwright/test`(chromium)を流用する。`pptxgenjs` / `jszip` も既存。新規依存なし。
- グラフのデータ payload は、当面 SVG の手描き幾何と並存する**限定的な二重表現**となる。FR-005 の整合チェックで乖離を封じ、SVG をデータから生成する完全な一元化は後続機能とする(「Deferred」参照)。
- 既存の 1280×720 キャンバス、DS トークン、`@media print` 単一ソース、`slides/*.html` の生成器運用の枠組みを踏襲する。
- 出力ファイル名 `dist/sample-deck.pptx` と Git 追跡(`.gitignore` の `!dist/sample-deck.pptx`)を維持する。

## Deferred(本機能の範囲外・後続)

| 項目 | 理由 | 後続の起動条件 |
|---|---|---|
| チャート SVG のデータ駆動生成 | 全視覚回帰ベースラインの再取得を伴い、本機能の中核価値(デッキ全体の一元化)に非依存 | FR-005 の整合チェックが恒常的に発火する、またはグラフ種を増やす要求が出た時点 |
| `.potx` テンプレート(空のレイアウト集)化 | 編集可能性ではなく配布形態の課題 | 利用者から「白紙から作り始めたい」要求が出た時点 |
| OOXML 直接生成による忠実度向上 | pptxgenjs の表現力で SC-004 は満たせる見込み | 近似幾何が実運用で受容されないと判明した時点 |
| フォント埋め込み | pptxgenjs 非対応(上流制約) | pptxgenjs が対応するか、出力経路を変更する時点 |
