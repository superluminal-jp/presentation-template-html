# Research: 編集可能 PPTX への DOM 実測変換

**Feature**: 011-pptx-dom-extraction | **Spec**: [spec.md](./spec.md)

Phase 0 の技術判断。各項目は「決定 / 根拠 / 棄却した代替案」で記す。

## D1: 変換方式 — DOM 実測抽出を採る

**決定**: 実レンダリングした `index.html` を Playwright で走査し、`getBoundingClientRect()` と
`getComputedStyle()` の実測値から PPTX を生成する。

**根拠**: 現行の手書きビルダーは正本と独立した第二の正本であり、計測上すでに乖離している
(未変換 8 枚、日本語リテラル 214 個、表紙メタの component 数が 12 対 20 で不一致)。
実測抽出は正本を一元化し、CSS の Flex/Grid をパースせずに済む — ブラウザが解いた結果を読むため、
レイアウト手法(Flex/Grid/絶対配置)に非依存になる。既存の `tests/visual/convertibility.spec.mjs` が
「名前付きスロットは矩形確定可能かつ実 DOM テキストを持つ」ことを 13 セレクタで既に検証しており、
この方式の前提は部分的に実証済み。

**棄却した代替案**:

- *手書きビルダーへの追補(案A)*: 8 枚を足せば一時的に整合するが、二重管理が残り乖離が再発する。今回の乖離自体がその反証。
- *OOXML 直接生成 / `.potx`(案C)*: 忠実度は最高だが実装・保守コストが大きく、SC-004(ネイティブ編集可能)は pptxgenjs で達成できる見込み。Deferred へ。
- *CSS パーサで静的解析*: Flex/Grid/折返しの解決を自前で再実装することになり、ブラウザの実測に劣る。

## D2: 抽出契約 — `data-pptx` 役割属性という明示的宣言

**決定**: DOM 要素に `data-pptx="text|shape|line|table|chart|image|group|ignore"` を付し、
変換器はこの語彙だけを知る。CSS クラス名(`.callout` 等)から種別を推論しない。

**根拠**: クラス名からの推論は、変換器がコンポーネント一覧を持つことと等価であり、FR-009
(新レイアウトへコード変更なしで追随)に反する。明示的な役割属性は、HTML 側が「PPTX で何になるか」を
宣言する契約となり、新規コンポーネント作者に対する設計ガイドとしても機能する。

**棄却した代替案**:

- *クラス名ベースの推論*: 変換器にコンポーネント辞書を持たせることになり、追随性を失う。
- *ヒューリスティック(テキストがあればテキストボックス等)*: 装飾と本文の区別がつかず、`.quote::before` のような境界事例で破綻する。

## D3: 擬似要素の本文 — 実 DOM 化する

**決定**: `styles/layouts/quote.css` の `.quote::before { content: "“" }` を、HTML 側の
`<span aria-hidden="true">` に置き換える。他の擬似要素(計 9 箇所中の残り)は純粋な装飾であり、
`data-pptx` 語彙の対象外として変換器が無視する。

**根拠**: DOM 抽出は擬似要素のテキストを取得できない。正本側で唯一の「擬似要素が本文文字を描く」箇所を
解消するのが、変換器に例外処理を持ち込むより安価かつ一般的。`aria-hidden` は装飾的引用符をスクリーン
リーダーから隠す既存の慣行に沿う。

**棄却した代替案**:

- *変換器で `::before` の `content` を読む*: `getComputedStyle(el, '::before')` で読めるが、矩形が取れず配置できない。
- *引用符を諦める*: 視覚回帰の差分となり FR-004 に反する。

## D4: チャート — データ payload を伴うネイティブグラフ

**決定**: 多系列 SVG に、系列名・カテゴリ・数値を持つデータ payload(`data-chart` の JSON)を付し、
`data-pptx="chart"` の要素として pptxgenjs の `addChart` へ写す。

**根拠**: 「編集可能な PowerPoint」の実質を最も大きく左右するのがグラフ。画像化された
グラフは数値を編集できず、要件の中核を落とす。現行の `data-series="N"` は系列**数**しか持たず、
ネイティブグラフの生成には値が要る。

**トレードオフ(記録)**: 当面、手描き SVG の幾何とデータ payload が並存する**限定的な二重表現**となる。
これは本機能が解消しようとしている重複と同種であるため、無条件には許容しない。FR-005 として
「payload の系列数 == `data-series`、payload の系列名 == `text.series-label` の文言」を自動検証し、
乖離を機械的に封じる。完全な一元化(SVG をデータから生成)は、全視覚回帰ベースラインの再取得を伴い
本機能の中核価値に非依存であるため Deferred とする。起動条件は spec.md の Deferred 表に記載。

**棄却した代替案**:

- *SVG をラスタ画像として貼る*: SC-004 に正面から反する。
- *SVG の幾何から数値を逆算する*: 棒の高さから値を推定する脆い変換になり、軸のスケールを別途宣言する必要が生じ、結局 payload と等価。

## D5: トークン解決値 — 手維持マップを廃し計算済みスタイルへ

**決定**: `scripts/pptx/tokens.mjs` の `COLOR` / `FONT` / `SIZE` の手維持マップは、要素ごとの
`getComputedStyle()` で置き換える。`THEME`(`theme1.xml` 差し替え用の配色スロット)のみ残し、
値は DS トークンを読んだ CSS 変数の解決値から取得する。

**根拠**: 同ファイルの冒頭コメントが「手維持マップ。将来 CSS から直接解決すればトークン変更に自動追従する」と
自ら課題として記している。要素の色は計算済みスタイルから直接得られるため、マップは中間の写経に過ぎない。
濃色スライドの前景色反転も、計算済みスタイルなら規則を再実装せず自動で拾える。

**棄却した代替案**:

- *マップを残しつつ CSS から生成する*: 生成物を第二の情報源として維持する必然性が無い(要素単位で直接読める)。

## D6: 中間表現(IR)を挟む

**決定**: 抽出(`extract.mjs`)と出力(`emit.mjs`)を、スライド IR という JSON 中間表現で分離する。
`build-pptx.mjs` は両者を繋ぐオーケストレータになる。

**根拠**: (a) 抽出はブラウザ内(`page.evaluate`)、出力は Node 側で走るため、境界が自然に存在する。
(b) IR をファイルに落とせば、PPTX を開かずに差分を検証でき、検証ゲート(D7)と障害調査が容易になる。
(c) 将来 OOXML 直接生成へ切り替える場合(Deferred)、抽出側を再利用できる。

**棄却した代替案**:

- *抽出結果から直接 pptxgenjs を呼ぶ*: 境界が曖昧になり、検証とデバッグの足場を失う。

## D7: 検証ゲート — 決定的チェックを `verify` に組み込む

**決定**: `scripts/pptx/check-pptx.mjs` を新設し、生成された PPTX を `jszip`(既存 devDependency)で
開いて (a) スライド数 == ライブ `.slide` 数、(b) 正本の各スライド見出しテキストが対応スライドの
XML に存在すること、を検証する。`package.json` の `verify` チェーンへ `build:pptx && check:pptx` を結線する。

**根拠**: 現行の乖離の構造的原因は `build:pptx` が `verify` の外にあること(`CLAUDE.md` に
「PPTX outside verify — not updated」と明記)。ゲートを閉じなければ本機能の成果は再び腐る。
`check:pdf` が同じ形(生成 → 決定的チェック → `verify` 結線)の先例であり、それに倣う。

**棄却した代替案**:

- *視覚比較(PPTX を画像化して HTML と比較)*: 幾何のピクセル一致が非目標である以上、恒常的に偽陽性を出す。
- *PPTX 生成の成否のみ確認*: 8 枚欠損・文言陳腐化のいずれも検出できない(現行と同じ穴)。

## D8: 実行時描画の待機

**決定**: 抽出前に、`js/tree-connectors.js` によるコネクタ描画と Web フォントの読み込み完了を待つ。
具体的には `page.goto(..., { waitUntil: 'networkidle' })` と `document.fonts.ready` の待機を行い、
コネクタ要素の存在を明示的に待つ。

**根拠**: tree コネクタは実行時に SVG を生成するため、待機なしでは抽出結果からコネクタが欠落する。
フォント未ロード時の実測矩形は最終レイアウトと異なり、テキストボックス寸法が狂う。

**棄却した代替案**:

- *固定時間の待機*: 非決定的で、CI での偽陰性の原因になる。
